# Discovery methods (Phase 5, v0.5)

Generated by `python scripts/gen_discovery_methods.py`: prose is written in that script; every table is produced from the code and from running the methods on the synthetic fixtures `syn-var-1` (injected brightness change) and `syn-hpm-1` (injected high proper motion). Fixture results are known-answer checks of the methods, **not facts about the sky**.

All six methods read a finished investigation record (and, for the inventory, the bundle manifest). None of them measures anything, calls a network service or a language model, or produces a probability. Each is versioned; the version appears in every output it produces.

| Method | Module | What it does |
|---|---|---|
| CAPREG-1 | `capabilities.py` | Registry of what Skytrace can do: methods, inputs, bounded parameters, outputs, limitations, tests, and where it runs (local / server / network), with current availability. |
| DISC-1 | `discovery.py` | Discovery engine stages A–G: evidence inventory, registered research questions with test plans, review links, rule-based next steps, record. |
| HYPO-1 | `hypotheses.py` | Competing explanations, each with deterministic tests over recorded values; six statuses; one published overall rule. |
| UNC-1 | `uncertainty.py` | What each recorded uncertainty is made of; bounds kept as bounds; sensitivity (STAB-1) kept separate; unquantified effects named. |
| REGDIAG-1 | `view.py` | Geometry of a pair's registration from the two Gaia-referenced plate solutions. |
| PKG-1 | `package.py` | Deterministic reproducibility package with checksums. |

## DISC-1 — discovery engine

**A · Inventory.** One row per evidence item (target, reference catalogue, every archive record, the run) with source, origin, epoch, channel, SHA-256 from the bundle manifest, quality and limitations. A field that is not recorded stays empty and is counted (`unknown_fields`); a field that does not apply is marked *not applicable*. Nothing is guessed.

**B · Questions.** A question is *answerable* when every required input is present, *answerable with limits* when some are, and *not answerable* when none are. Three questions are registered as not answerable by design.

| ID | Question | Required inputs | Method |
|---|---|---|---|
| Q-VAR | Did the target's brightness change between wavelength-matched observations? | ≥ 1 wavelength-matched pair with usable photometry; ≥ 1 pair with ≥ 3 matched reference stars (calibrated comparison) | WLMATCH-2 pairing, PAIRDIFF-1/2 comparison, CALCHECK-1 error scale, ASSESS-2 decision |
| Q-MOT | Does the target move, and does its motion agree with the catalogue? | ≥ 2 exposures with a usable target position and plate solution; ≥ 2 visits for the visit-averaged fit | REFSEL-2 references, PLATE-LOO-1 plates, EPHEM-AA-LP-1 parallax, LINFIT-EPOCH-1 fit, ASSESS-2 decision |
| Q-COMPAT | Can two chosen observations be compared for brightness? | ≥ 2 measured observations with a wavelength at the target | WLMATCH-2 on the two logged measurements (Time Machine) |
| Q-SENS | Which analysis choices change the result? | a finished analysis | STAB-1: aperture ±0.5 px, tolerance 0.3, clip 3σ/6σ |
| Q-ALT | Which explanations remain viable? | a finished analysis | HYPO-1 rule-based tests on recorded values |
| Q-UNC | What are the uncertainties made of? | a motion fit or a matched pair | UNC-1 decomposition of logged σ terms |
| Q-QUAL | How much of the data is usable, and why were exposures rejected? | ≥ 1 measured exposure | status codes from measurement; ASSESS-2 data-quality outcome |
| Q-REPRO | Can this result be reproduced from the stored files? | the bundle and the record | PROVCHECK-1 (hashes, origins, codes, re-run determinism) |
| Q-CAUSE | What physically causes the change? | not answerable: needs time-resolved spectra or data from other instruments and a physical model; SKYTRACE measures change, not cause | — |
| Q-DISCOVERY | Is this a new astronomical discovery? | not answerable: no single analysis establishes a discovery; it needs real archive data, independent confirmation and expert review | — |
| Q-DIST | How far away is the target? | not answerable: no distance is measured; the catalogue parallax is quoted and used only to correct positions | — |

**C · Test plan** per question: required inputs (available / missing), method versions, preconditions, assumptions, expected outputs, validation and limitations. **D · Execution** links each plan to the workspace where it runs; the engine does not execute anything itself. **E · Review** links outcomes (ASSESS-2), the evidence matrix (HYPO-1) and the uncertainty decomposition (UNC-1). **F · Next steps** are rules over outcomes, inventory and registry; each states the question it addresses, the data it needs, what it can and cannot establish, and the service it needs when that service is unavailable. No step promises a gain in confidence. **G · Record**: the research question and user hypotheses are saved with the investigation; the package adds inventory, tests and checksums.

## HYPO-1 — hypothesis tests

Statuses: consistent, contradicted, inconclusive, not_tested, evidence_unavailable, incompatible. Overall rule (identical in `web/js/rules.js`, parity-tested over every combination of up to three tests): *any contradicted test → contradicted; else any consistent test → consistent so far; else all untested → untested; else inconclusive*.

A test reads values already in the record and applies the stated rule. Explanations without an implemented test are listed as *not tested* rather than omitted, so unequal evidence stays visibly unequal. User-written hypotheses are stored as interpretations and can only cite these recorded tests.

| Explanation | Test | Rule | syn-var-1 | syn-hpm-1 |
|---|---|---|---|---|
| V-INTRINSIC: The source's brightness changed between the epochs. | T-SIG: A reference-calibrated matched pair differs by ≥ 5σ | \|z_cal,scaled\| ≥ 5 in at least one pair | consistent | inconclusive |
| V-INTRINSIC: The source's brightness changed between the epochs. | T-REPEAT: The change appears in more than one detector | significant pairs on ≥ 2 detectors | consistent | not tested |
| V-CALIB: A calibration change between the exposures explains the difference. | T-REFRATIO: Dividing by the reference stars' flux ratio removes the difference | raw \|z\| ≥ 5 pairs fall below 5σ after PAIRDIFF-2 | inconclusive | not tested |
| V-ERRMODEL: Underestimated measurement errors explain the difference. | T-CALCHECK: Constant reference stars show the stated errors are too small to explain it | CALCHECK scale > 3, or significance gone after scaling | contradicted | inconclusive |
| V-WAVELENGTH: A wavelength difference within the matching tolerance, acting on the spectrum, explains it. | T-SLOPE: Expected flux change from the local spectral slope across \|Δλ\| | needs a spectral-slope model | not tested | not tested |
| V-BLEND: An unresolved neighbour contributes to the difference. | T-NEIGHBOUR: Flux of uncatalogued neighbours inside the aperture | needs PSF-fitting photometry | not tested | not tested |
| M-CATALOGUE: The measured motion is the catalogued proper motion. | T-CATZ: Measured motion agrees with the catalogue | \|measured − catalogue\| ≤ 3σ per axis | inconclusive | consistent |
| M-STATIC: The source does not move. | T-DET: No significant motion | \|pm\|/σ < 5 | inconclusive | contradicted |
| M-REGISTRATION: Registration errors produce the apparent motion. | T-REG: Registration residual is comparable to the measured displacement | 3 × median plate RMS ≥ \|pm\| × baseline | not tested | contradicted |
| M-PARALLAX: Unmodelled parallax produces or biases the apparent motion. | T-PLX: Unremoved parallax is large enough to bias the rate | parallax rate bound ≥ σ(pm) | contradicted | contradicted |
| M-REFS: Faulty reference stars bias the plate solutions. | T-REFSEL: Reference stars were quality-checked and outliers removed | inspect REFSEL-2 counts and leave-one-out plate rejections | inconclusive | inconclusive |
| M-CHROMATIC: Detector-dependent (chromatic) offsets produce the apparent motion. | T-PERDET: Motion fitted separately per detector agrees | needs per-detector fits | not tested | not tested |

## UNC-1 — uncertainty decomposition

Motion: the statistical error of the primary (visit-averaged) fit, the per-exposure fit as a cross-check, the number of visits whose scatter used the empirical floor, the catalogue proper-motion error, and the parallax systematic converted to a rate bound over the baseline — labelled a **bound, not a standard deviation**, and never added in quadrature.

Brightness: for each matched pair the PAIRDIFF-2 denominator is recomputed from its logged inputs (the two exposures' flux errors and the reference-ratio scatter), its variance shares are reported, and the recomputed z is compared with the logged z (`consistent_with_log`). Any mismatch is shown, not hidden.

Sensitivity to analysis choices (STAB-1) is shown beside, never inside, a σ.

Effects that no method here quantifies (listed in the interface and the package):

* **Aperture correction** — aperture fluxes are compared only between matched pairs, where it cancels to first order; the residual sub-pixel term is not modelled (the calibration check measures its effect on reference stars)
* **PSF variation across the detector** — a Gaussian PSF is fitted; no PSF-model uncertainty is propagated
* **Chromatic centroid offsets** — per-detector motion fits are not implemented, so detector-dependent offsets are not separated
* **Unresolved, uncatalogued neighbours** — only catalogued neighbours are masked; others contribute to flux and centroid without an error term

* `syn-var-1`: motion decomposition available; 46 matched pairs, the 8 largest decomposed, 8 of 8 calibrated pairs recompute exactly to the logged z.
* `syn-hpm-1`: motion decomposition available; 43 matched pairs, the 8 largest decomposed, 7 of 7 calibrated pairs recompute exactly to the logged z.

## REGDIAG-1 — registration diagnostics

From each exposure's Gaia-referenced plate solution (linear part of the gnomonic fit): pixel scale along x and y (arcsec/px), x-axis position angle, number of reference stars and leave-one-out residual RMS (mas). For the pair: rotation and scale ratio of B relative to A, the target pixel in A, the pixel in B that sees the same sky point, and the shift. Geometric only; it says nothing about photometric calibration. The browser port (`web/js/static/compare.js`) is parity-tested against Python. The registration-limit test T-REG uses the same residuals: a motion is *registration limited* when 3 × the median plate RMS is at least |proper motion| × baseline.

* `syn-var-1`: diagnostics available for 46 of 46 accepted pairs (the rest lack a plate solution for one exposure).
  First such pair: rotation 0.7643°, scale ratio 0.999851, shift (7.31, -4.62) px; plate RMS 209 and 517 mas.
* `syn-hpm-1`: diagnostics available for 26 of 43 accepted pairs (the rest lack a plate solution for one exposure).
  First such pair: rotation -0.1013°, scale ratio 0.999328, shift (1.51, 4.19) px; plate RMS 182 and 86 mas.

## PKG-1 — reproducibility package

`GET /api/investigations/{id}/package.zip` (and *Report Studio → Reproducibility package*). One folder `skytrace-<hash16>/` containing README.md, record.json (byte-identical to the record export), report.md, discovery.json, evidence_graph.json, capabilities.json, bundle_manifest.json and SHA256SUMS. Member order and timestamps are fixed, so the same inputs give the same bytes (tested). Verify with `sha256sum -c SHA256SUMS`; the record's content hash recomputes from record.json; replay needs the data bundle named in the manifest. No image data is included.
