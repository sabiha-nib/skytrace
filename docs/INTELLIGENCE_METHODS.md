# Scientific intelligence methods (Phase 9)

Generated by `python scripts/gen_intelligence_methods.py` from the code and from the intelligence report the API serves for the two synthetic fixtures (`syn-var-1`, a variable source; `syn-hpm-1`, a high-proper-motion source). Fixture results are known-answer checks of the software on generated data; they are not facts about the sky. No method here calls a model, uses a probability or produces a score. The browser ports of the session-dependent rules (`web/js/intelcore.js`) are parity-tested against these modules (`tests/unit/test_intelligence.py::test_browser_intelligence_functions_match_python`).

## MEMORY-1 — research memory

Memory items are of kinds observation, conclusion, explanation, failure, question, assumption, with statuses verified, provisional, assumption, outdated, unverifiable. A competing explanation stays 'provisional' however often it is remembered as consistent: memory never turns a hypothesis into a fact. Recall maps query words onto a fixed vocabulary of 16 concepts. Failure warnings quote the recorded reason when an action you are about to take failed before on the same target.

| Rule | Statement |
|---|---|
| M1 | a recorded count, measurement summary or recorded failure from a record whose content hash recomputes is 'verified' |
| M2 | a conclusion that is not established, and every explanation or question, is 'provisional' |
| M3 | an analysis choice or method premise is an 'assumption' |
| M4 | an item superseded by a later record of the same target (newer analysis version or other method version for that question) is 'outdated' |
| M5 | an item from a record whose content hash does not recompute is 'unverifiable' |
| M6 | an explanation is never 'verified'; 'consistent' means still viable, 'contradicted' means rejected by a stated rule |

Corpus at generation time (2 investigations: the fixtures plus any saved records): assumption 48, provisional 62, verified 65.

## DGENOME-1 — discovery genome

Thirteen fields per question, each citing graph objects or record paths: original_observation, data_source, measurement_characteristics, initial_anomaly, detection_method, candidate_explanations, rejected_explanations, supporting_evidence, contradictory_evidence, uncertainty_structure, validation_procedures, final_interpretation, remaining_unknowns. Comparison is structural (shared characteristics, interpretations, weaknesses, uncertainty structure, reusable methods) and carries no score; a match is not evidence that two sources are physically alike.

## ORACLE-1 and EVNEG-1 — observation oracle and evidence negotiation

Hypothetical observation plans are evaluated under the measurement model that reproduces the recorded fit (threshold 5.0 σ, at most 20 added visits). The expected Δχ² between the hypotheses is S² + 1 for a significance S. Information gain in bits is not computed, because it needs prior probabilities that no record defends. Plans are never presented as scheduled observations.

## MDNET-1 — multi-discovery network

A relationship exists only where a rule matches; each edge states its basis and limitation. Shared keywords never create an edge.

| Rule | Relationship | Limitation |
|---|---|---|
| N1 | same target | sibling runs share data by construction; the parameter differences are what distinguish them |
| N2 | conflicting conclusion | the answer depends on an analysis choice; neither run is thereby wrong |
| N3 | shared anomaly | the same outcome category, reached by the same rules; not evidence of a common cause |
| N4 | shared measurement characteristics | similar sampling and coverage; not physical similarity |
| N5 | repeated analytical weakness | the same stress mode is weak in both; check whether one cause explains both |
| N6 | shared viable explanation | the same explanation remains open in both; it is not more likely for that |
| N7 | reusable method | the inputs exist; whether the method suits the other target is not checked |
| N8 | shared failure | the same refusal recurs; it may be a property of the data or of the method |
| N9 | related catalogue parameters | catalogue inputs within 25 %; not a measured result of either investigation |

Corpus at generation time: 1 edge(s).

## REPRONET-1 — reproduction network

A manifest records data hashes, software and environment, configuration, seed, stage hashes and limitations. Two manifests compare into one of: exact match, different input data, methodological, missing dependency, numerical, unexplained divergence. A matching re-execution shows that a result repeats, not that it is valid.

## FINGERPRINT-1, INSTCHECK-1 and BUDGET-1

The sensitivity fingerprint recomputes each conclusion along six dimensions (thresholds, calibration, error model, preprocessing, model selection, data selection) and reports stable, changes, not tested, not applicable, never a score. The instrumental reality check covers detector dependence, calibration, error model, wavelength sampling, blending, registration, reference frame, chromatic offsets, excluded exposures; ruling every one out does not make a signal astrophysical. The uncertainty budget classes every term as measured, estimated, unquantified; variance shares are given only where terms add in quadrature (the PAIRDIFF-2 denominator).

## CYCLE-1 — research cycle with bounded autonomy

The cycle proposes registered actions only, by these rules. Advisory executes nothing; supervised executes each step you approve; restricted automation runs the predefined workflow after one authorization. No level grants network or write permission.

| Rule | Statement |
|---|---|
| A1 | the integrity gate's 'Reproducible' requirement is not met |
| A2 | the fingerprint dimension 'preprocessing' is not tested |
| A3 | a major or critical challenge is open |
| A4 | a competing explanation has never been tested |
| A5 | the uncertainty budget lists unquantified effects |
| A6 | always: start from the data-quality checks |

| Level | Permission classes allowed | Executes |
|---|---|---|
| Advisory | none | nothing: proposes actions only |
| Supervised | inspect, analysis | each step you approve, one at a time |
| Restricted automation | inspect, analysis | the predefined workflow, after one authorization that lists every step |

Restricted workflow: check_quality, evaluate_hypotheses, decompose_uncertainty, challenge_interpretation, reproduce_independent.

## CAPSULE-1 — time capsule (browser)

A capsule freezes the record hash, the gate, the unknown map and the session items at a moment, with a SHA-256 digest of its content. A digest makes later edits detectable; it is not a signature and not cryptographic immutability.
