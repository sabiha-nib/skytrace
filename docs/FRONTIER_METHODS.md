# Frontier methods (Phase 7, v0.7)

Generated by `python scripts/gen_frontier_methods.py`. Prose is written in that script; every table is produced from the code or by running the methods on the synthetic fixtures `syn-var-1` (injected brightness change) and `syn-hpm-1` (injected high proper motion) and on generated Synthetic Observatory scenarios. These are known-answer checks of the software, **not facts about the sky**; agreement on generated data does not establish performance on real SPHEREx observations.

None of these methods measures anything new, produces a probability or a score, or calls a model. They re-assess recorded inputs, re-run the deterministic pipeline on stated changes, generate labelled synthetic data, or apply documented rules to a finished record.

| Method | Module | What it does | What it never does |
|---|---|---|---|
| CF-1 | `counterfactual.py` | One stated change against a named baseline (parameter, exclusion, threshold, error scale, method); re-runs or re-assesses and compares. | Modify the original record or bundle; present a simulated value as observed. |
| SYNOBS-1 | `synthobs.py` | Generates a bounded scenario as a SYNTHETIC bundle under data/synthlab, runs the unchanged pipeline, compares with ground truth. | Write to data/bundles or fixtures; replace observations. |
| OBSDES-1 | `synthobs.py` | Generates 2–3 hypothetical schedules with the same truth and compares recovered sensitivity and outcomes. | Schedule a telescope; claim instrument performance. |
| ASL-1 | `adversarial.py` | Challenges from documented rules over the record, hypotheses, quality, ledger, uncertainty, stability and session. | Claim a flaw no rule establishes; hide a challenge you acknowledged. |
| INFO-1 | `infogain.py` | Orders open hypothesis tests by feasibility and the viable explanations they bear on. | Compute information gain (there is no probability model). |
| REPRO-1 | `repro.py` | Eleven checks and one of four verdicts; replay compared by content hash. | Count a successful import as reproduction; produce a score. |
| REVIEW-1 | `review.py` | Five deterministic reviewer rule sets; every finding cites a record field or session item. | Simulate reviewers or agents. |
| TWIN-1 | `twin.py` | Hashed, versioned computational records of an observation, target, analysis, scenario or session; structural diff. | Model an astronomical object physically. |
| SPE-1 / HORIZON-1 | `possibility.py` | Six investigation layers and research-opportunity cards from ten rules over recorded state. | Invent counts or findings; rank by a hidden score. |
| CAPREG-3 | `capabilities.py` | Registry with six new actions and a permission class per action; autopilot levels. | Let a plan run an unregistered action or reach the network. |

## CF-1 Counterfactual Universe Lab

Bounds (from the code): thresholds `variability_z` 2.0–10.0, `motion_detect_sigma` 2.0–10.0, `catalogue_consistency_sigma` 1.0–5.0; photometric error factor (1.0, 5.0]; at most 40 excluded observation keys. Exclusion works on a copy of the bundle index (recorded as selection rejection `counterfactual_exclusion`); the files on disk are untouched. Threshold, error-scale and method scenarios re-assess the recorded inputs; with no change, re-assessment reproduces every recorded outcome exactly (tested on both fixtures).

Value labels:

- **observed** — read from the data files
- **derived** — computed from observed values by a recorded method
- **simulated** — a deliberate perturbation for the scenario
- **assumed** — a setting chosen for the scenario
- **hypothetical** — a scenario that did not happen; not an alternative physical reality

## REPRO-1 Reproducibility challenge

Importing a record proves only that it parses. The verdict is *reproduced* only when a re-execution here gives the identical content hash and every other check passes; *replayable, not replayed here* when nothing failed but no replay ran; *not reproducible as recorded* when a replay or integrity check failed; *incomplete* when inputs or required metadata are missing.
