## Provenance records

Every retrieved byte gets a `Provenance` record (`src/skytrace/provenance.py`):

```json
{"source": "IRSA", "source_url": "<exact URL requested>", "retrieved_at": "<UTC time of the live request>",
 "origin": "live | cache | fixture | synthetic", "dataset_id": "10.26131/IRSA662", "release": "QR3",
 "content_sha256": "<hash of the bytes>", "processing": [], "notes": ""}
```

- When a response is served from the local cache, it is labelled `cache` and keeps the time of the original live request. It is never relabelled `live`. A cache entry whose bytes no longer match its hash is treated as missing.
- A fixture is accepted only if it has a provenance sidecar file; it is then labelled `fixture`.
- Synthetic data use `source = "synthetic"`, `origin = "synthetic"`. Any other combination is refused at construction.
- Each analysis step logs the provenance of the files it used. Reports list every distinct source with its origin.

## Bundles

`scripts/acquire_targets.py` writes `data/bundles/<target>/`:

| File | Content |
|---|---|
| `images/<release>_<obs_id>_D<n>.fits` | the cutout exactly as returned by IRSA (written atomically, never modified) |
| `discovery.json` | every image the archive returned, with inclusion or the exclusion reason; the search URL, time and origin per release; selection criteria SEL-1 |
| `target.json` | SIMBAD identity (with coordinate and proper-motion bibcodes) and Gaia DR3 astrometry, with the supplied-coordinate separation when given |
| `references.json` | Gaia DR3 reference stars and the query that produced them |
| `inspection.json` | the real FITS structure per release/detector: extensions, units, shape, WCS types, time and flag keywords, reader used |
| `manifest.json` | every file with SHA-256, size, role and provenance; kind `archive` |

`bundle.verify()` checks: every listed file exists with matching size and SHA-256; no unlisted files; required files present; archive bundles have `inspection.json`; provenance origins match the kind; no FITS file in an archive bundle has `SYNTHETIC = T`, and every FITS file in a synthetic bundle does. The server refuses to analyse a bundle that fails verification.

**Status:** no archive bundle exists in this build. `fixtures/synthetic/` contains two synthetic bundles (51 files, 3.9 MB each), generated by `scripts/make_synthetic_fixtures.py`.

## Processing performed

Nothing is written back to the original files. Derived products (measurements, pairs, fits, outcomes) live only in investigation records, which carry the bundle manifest's SHA-256, all parameters, method IDs, software versions and a content hash.
