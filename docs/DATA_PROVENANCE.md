## Provenance records

Every retrieved byte gets a `Provenance` record (`src/skytrace/provenance.py`):

```json
{"source": "IRSA", "source_url": "<exact URL requested>", "retrieved_at": "<UTC time of the live request>",
 "origin": "live | cache | fixture | synthetic", "dataset_id": "10.26131/IRSA662", "release": "QR3",
 "content_sha256": "<hash of the bytes>", "processing": [], "notes": ""}
```

- When a response is served from the local cache, it is labelled `cache` and keeps the time of the original live request. It is never relabelled `live`. A cache entry whose bytes no longer match its hash is treated as missing.
- A fixture is accepted only if it has a provenance sidecar file; it is then labelled `fixture`.
- Synthetic data use `source = "synthetic"`, `origin = "synthetic"`. Any other combination is refused at construction.
- Each analysis step logs the provenance of the files it used. Reports list every distinct source with its origin.

## Bundles

`scripts/acquire_targets.py` writes `data/bundles/<target>/`:

| File | Content |
|---|---|
| `images/<release>_<obs_id>_D<n>.fits` | the cutout exactly as returned by IRSA (written atomically, never modified) |
| `discovery.json` | every image the archive returned, with inclusion or the exclusion reason; the search URL, time and origin per release; selection criteria SEL-1 |
| `target.json` | SIMBAD identity (with coordinate and proper-motion bibcodes) and Gaia DR3 astrometry, with the supplied-coordinate separation when given |
| `references.json` | Gaia DR3 reference stars and the query that produced them |
| `inspection.json` | the real FITS structure per release/detector: extensions, units, shape, WCS types, time and flag keywords, reader used |
| `manifest.json` | every file with SHA-256, size, role and provenance; kind `archive` |

`bundle.verify()` checks: every listed file exists with matching size and SHA-256; no unlisted files; required files present; archive bundles have `inspection.json`; provenance origins match the kind; no FITS file in an archive bundle has `SYNTHETIC = T`, and every FITS file in a synthetic bundle does. The server refuses to analyse a bundle that fails verification.

**Status:** no archive bundle exists in this build. `fixtures/synthetic/` contains two synthetic bundles (51 files, 3.9 MB each), generated by `scripts/make_synthetic_fixtures.py`.

## Processing performed

Nothing is written back to the original files. Derived products (measurements, pairs, fits, outcomes) live only in investigation records, which carry the bundle manifest's SHA-256, all parameters, method IDs, software versions and a content hash.

## Record-level verification (v0.3)

Every measurement event's provenance now carries the SHA-256 of the stored file from the manifest (earlier
records left it empty for synthetic bundles; PROVCHECK-1 found this). `scripts/verify_provenance.py` traces a
record back to the bytes it was computed from; see [REPRODUCIBILITY.md](REPRODUCIBILITY.md).

## Derived reports and packages (v0.5)

The discovery report (DISC-1), hypothesis tests (HYPO-1), uncertainty decomposition (UNC-1) and evidence graph are
computed from the investigation record and the bundle manifest only; each carries the record's content hash and its
method version. The evidence inventory takes every SHA-256 from the bundle manifest and leaves a field empty, and counts
it, when the manifest or record does not state it. The reproducibility package (PKG-1) contains the record byte for
byte, the bundle manifest, and SHA256SUMS over every member; it contains no image data. In the static preview these
files were produced by the server at build time and are listed in `PREVIEW_MANIFEST.json` with their checksums.

## Research sessions and Phase 6 readers (v0.6)

* **Sessions** (SESSION-1) refer to analysis runs by investigation id *and* content hash; a reference block in the notebook
  resolves against the run whose hash it names, and says so when that run is not loaded. A session's own hash (SHA-256 over its
  SKY-CANON-1 text without `content_hash`) is verified on every save, load and import; an import with a different hash is refused.
  Server sessions live in `data/sessions/` (git-ignored); the static preview keeps them in this browser's storage.
* **Compatibility, data quality, ledger and radar** (COMPAT-1, DQ-1, LEDGER-1, RADAR-1) read the record, the bundle manifest and
  the discovery index; the research report carries the record's content hash and is cached by it. DQ-FILES re-hashes bundle files
  when the bundle directory is available and reports *not checked* otherwise (e.g. through the copilot).
* **Experiments** (EXP-1) re-execute `analysis.run` on the bundle; each run keeps its parameters, timing, outcome categories and
  content hash. A negative control names the fixture used and its generator input (the truth by construction).
* **Assistant drafts** in the notebook carry their source (local deterministic assistant or verified external model) and the
  question; they are labelled `[draft]` in exports until accepted.
* **Connectors** (ACQ-2) record nothing from the network in this environment: the previews are built by the acquisition code
  with a recorder in place of the transport, and say so. Every service was refused by the proxy (`data/environment_report.json`).

## Frontier laboratory (v0.7)

* **Counterfactual scenarios** (CF-1) name their baseline by content hash. The baseline is recomputed from its parameters and
  refused if the hash differs. Each scenario has its own `scenario_hash` over the canonical scenario. Every compared value is
  labelled observed, derived, simulated, assumed or hypothetical. Exclusions act on a copy of the bundle index, logged as
  selection rejection `counterfactual_exclusion`; no bundle file is touched. A scenario twin (TWIN-1) lists the baseline hash it
  derives from.
* **Synthetic Observatory bundles** (SYNOBS-1) are written to `data/synthlab/syn-lab-<hash12>/` (git-ignored; set with
  `SKYTRACE_SYNTHLAB_DIR`). They are never written to `data/bundles/` or `fixtures/`. Files carry `SYNTHETIC = T`, origin
  `synthetic`, target names `SYN-LAB-…`, the generator version, scenario, seed and ground truth. The provenance stamp is fixed
  (`2026-01-01T00:00:00+00:00`) so that output is byte-reproducible. It is not the time of generation, and the documentation says
  so. A cached bundle is reused only after its checksums verify.
* **Frontier reports** (SPE-1, HORIZON-1, ASL-1, INFO-1, REVIEW-1, REPRO-1, TWIN-1) carry the record's content hash and are
  cached by it, plus the digest of a stability result when one is used. Challenges and review findings cite record fields
  (`events[step].data…`, ledger claims, hypothesis tests) or session items.
* **Session additions**: `scenarios`, `synthetic`, `causal` (labelled user-proposed) and `autopilot` runs (level, steps,
  statuses, errors). Each is appended to the session history with a hash-verified save.
