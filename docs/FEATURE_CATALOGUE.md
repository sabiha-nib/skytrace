# Skytrace feature catalogue

Generated by `python scripts/feature_catalogue.py` from the data in that script; counts are computed. Checked by `tests/unit/test_feature_catalogue.py` (well formed; every cited verification file exists; every implemented concept cites one).

Note: the Phase 5 brief asked for at least 250 concepts across 25 domains, scored 1–5 on seven dimensions with tiers A–D. The domain list and the seven dimensions below are this project's own breakdown; they were written for this catalogue rather than copied from the brief.

This is the Phase 5 (0.5) catalogue. Later phases have their own, each deduplicated against the earlier ones: [PHASE6_CATALOGUE.md](PHASE6_CATALOGUE.md) (0.6), [PHASE7_CATALOGUE.md](PHASE7_CATALOGUE.md) (0.7), [PHASE8_CATALOGUE.md](PHASE8_CATALOGUE.md) (0.8, the epistemic layer) and [PHASE9_CATALOGUE.md](PHASE9_CATALOGUE.md) (0.9, the scientific intelligence layer: 600 concepts in 50 domains, a roadmap with categories A–D).

**267 concepts in 25 domains.** Status: 104 existing (≤ 0.4), 61 deferred, 31 out of scope, 71 new in 0.5. Tiers: A 79, B 92, C 44, D 52.

Scores (1–5): **S** scientific value, **U** user value, **D** differentiation, **F** feasibility now, **R** data readiness, **V** verifiability, **K** integrity safety (5 = little risk of misleading).
Tier: value = mean(S, U, D), practicality = mean(F, R, V, K). A: value ≥ 4 and practicality ≥ 4 · B: value ≥ 3 and practicality ≥ 3.5 · C: value ≥ 2.5 · D: otherwise, and always for out-of-scope concepts. A tier is a priority signal; the status says whether something is built.
