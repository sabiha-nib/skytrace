# Internationalisation (I18N-1) — six interface languages

Skytrace 0.10 runs in English (`en`, the source language and default), বাংলা (`bn`), हिन्दी (`hi`), Español (`es`), Français (`fr`)
and Deutsch (`de`). This document describes how it works, what is and is not translated, how translations are checked, and the
state of the translations in this release.

**All five translations were written by an AI model (Claude, Anthropic) and have not been reviewed by a native speaker or a
domain expert.** Every language file says so (`status`, `translator`, `reviewed: false`); the interface says so in the settings
dialog, in Multilingual Research and in every translated report.

## 1. Architecture

| Part | File | What it does |
|---|---|---|
| Catalogue | `web/i18n/catalog.json` (generated) | every interface message as `{k, s}`: the English text `s` is the message id (gettext style), `k` its key (first 10 hex digits of SHA-1) |
| Source inventory | `web/i18n/source.json` (generated, not shipped in the preview) | each message with its kind (text, pattern, vocabulary, keyed) and the files it comes from |
| Keyed messages | `web/i18n/en.json` | messages written for translation with named parameters and plural forms (`count.*`, `explain.*`) |
| Language files | `web/i18n/{bn,hi,es,fr,de}.json` | translations by key, plural forms, status, translator, version, review flag |
| Terminology | `web/i18n/terms.json` (generated by `scripts/i18n_terms.py`) | TERM-1: 48 scientific terms in six languages |
| Quality | `web/i18n/quality.json` (generated by `scripts/i18n_quality.py`) | I18N-Q1 counts per language |
| Browser runtime | `web/js/i18n.js` | loads the catalogue and the language, translates the document, formats numbers and dates, `t(key, params)` |
| Server runtime | `src/skytrace/i18n.py` | the same files for reports and exports: `_t("English {0}", lang, value)` |
| Fonts | `web/fonts/` | Noto Sans Bengali and Noto Sans Devanagari (SIL Open Font License, `OFL.txt`), loaded by `unicode-range` |

**Extraction.** `python scripts/i18n_extract.py` collects interface text from `web/index.html` (text nodes and the attributes
`aria-label`, `title`, `placeholder`), string and template literals in `web/js/**/*.js` that read as interface text, server text
marked `_t("…")` in `src/skytrace/**/*.py`, controlled vocabulary and notes from the engines (`VOCAB_SOURCES`, `LONG_SOURCES`), and
the keyed messages. A template literal becomes a pattern: `${…}` turns into `{0}`, `{1}`, … Filters drop markup, CSS selectors,
class lists, identifiers, paths, colours and key names. `--check` fails when the generated files are stale.

**Runtime translation.** On a language change `i18n.js` translates every text node and the attributes `aria-label`, `title`,
`placeholder`, `alt`, and a `MutationObserver` translates whatever the application renders afterwards. A text node is looked up
exactly; if it is a pure number or ISO date it is localised; otherwise it is matched against the patterns (most specific first),
and the substituted values are kept — numbers inside them are re-expressed in the language's number format with the same digits
and decimals. A pattern whose only fixed text is a connective (`{0} of {1}`, `{0} and {1}`) matches numbers only, so it
can never translate part of a recorded English sentence. Switching back to English restores the original text (the source is remembered per node). Skipped by design:
`script`, `style`, `code`, `pre`, `textarea`, `.mono`, `[translate=no]`, `[data-i18n-skip]`, `[contenteditable]` (a text box's
content is the user's own text, but its placeholder and title are still translated).

**Keyed messages and plurals.** `t("count.observations", {n})` picks the plural form with `Intl.PluralRules` for the current
language; a missing translation falls back to English, then to the key.

**Numbers and dates.** `Intl.NumberFormat` per language (Bangla uses Bengali digits by default; Hindi uses Western digits, as its
CLDR default does). Settings → Numerals switches to Western digits (`latn`) in every language. Decimals are never added or
dropped; long plain integers (identifiers) and years are left alone. Dates are UTC throughout and keep "UTC" after localisation.

**Persistence.** The language is kept in `localStorage` (`skytrace.lang`; numerals in `skytrace.digits`), can be overridden by
`?lang=xx` in the URL, and is written to the open research session's `preferences` (so a session reopened elsewhere carries it;
it is applied when the browser has no stored choice). Reports and exports record the language they were written in.

## 2. What is translated and what is not

Translated: every interface label, heading, button, tab, tooltip, accessibility label, placeholder, empty state, loading state,
error and validation message, help and glossary entry, keyboard-shortcut description, the vocabulary the engines display as
labels (statuses, outcome categories, region names), Phase 10 notes and rules, explanations (EXPLAIN-1) and report wording.

Not translated, by design:
- numbers, units and symbols (µm, mas, σ, χ²), identifiers (observation ids, hashes, run ids), method identifiers (WLMATCH-2,
  PAIRDIFF-2, …), file names, JSON field names, API fields and internal keys;
- narrative text recorded by the scientific engines (outcome statements, rule details, limitations, readings that embed values):
  it is scientific content in its original language and is shown unchanged, marked `lang="en"` where it appears inside translated
  views. Translating it could change a conclusion;
- JSON exports (records, handoffs, manifests): their content is language-independent; a handoff states the interface language it
  was prepared in and that its content is English.

## 3. Reports in six languages

`GET /api/investigations/{iid}/report.md?lang=xx` writes the Markdown report with translated wording and every value unchanged.
It begins with a metadata comment — language, translation status, translator — and a notice that numbers, identifiers, units,
method names and engine statements are given unchanged in English. In the static preview the browser applies the same dictionaries
to the recorded English report (`localizeExport`); code blocks and table rows of recorded values are not touched. The Open Science
Gateway downloads the report in any of the six languages without changing the interface language.

Verified by `tests/unit/test_phase10.py::test_report_in_six_languages_keeps_every_number_and_engine_statement` (the multiset of
numbers in every language equals English; every outcome statement and the parameter block appear verbatim) and
`tests/integration/test_api.py::test_phase10_universal_and_multilingual_report`.

## 4. Terminology (TERM-1)

48 terms (astrometry, photometry, spectroscopy, statistics, reasoning, data, reproducibility, time series, instrument) with the
canonical English term, a definition, context and units, and for each language the term the interface uses, accepted synonyms,
the stems used by the consistency check, a definition, and for Bangla and Hindi a romanised pronunciation. Where no settled
equivalent exists the recognised technical term is kept (e.g. Bangla "ফটোমেট্রি", German "Pipeline") and explained. Units,
symbols and method identifiers in definitions are checked to survive translation.

## 5. Cross-language search (XSEARCH-1)

Layers, each labelled in the results: (1) exact text after normalisation (NFKC, lower case, Latin diacritics removed); (2)
terminology mapping — the query contains a term or synonym from TERM-1 in any language, and the item contains its canonical
English form or its interface-language form; (3) lexical — every remaining word, or a shared stem of five letters or more.
Ranking is a stated order (layer, then number of terms matched, then input order), not a score. **It is not semantic search**:
no embedding model is available, and the interface says so. Script detection reports Bangla, Devanagari, Latin or mixed. Used in
Multilingual Research and in the command palette. Python and browser implementations are parity-tested.

## 6. Quality checks (I18N-Q1)

Automated, in `tests/unit/test_phase10.py` and `scripts/i18n_quality.py`:
- completeness: every catalogue message and keyed message in every language (release-blocking test);
- placeholders identical; no U+FFFD or control characters; NFC form;
- every digit sequence and method identifier of the English message present in each translation;
- Bangla and Hindi prose written in their own scripts;
- terminology consistency: every message containing a TERM-1 term uses an accepted form in each language (inconsistencies are
  listed for review; quoted identifiers are excluded);
- text expansion per language (median and maximum ratio), the longest expansions listed;
- generated files up to date.

In the interface (Multilingual Research → Translation quality): the counts above, messages rendered without a translation in this
browser, and a live check for clipped text on the current page. Counts, never percentages.

State in this release: 3,668 interface messages and 16 keyed messages, all translated in all five languages; 0 placeholder,
Unicode, number or identifier problems; terminology consistent in 685 messages per language with 0 inconsistencies; median text
expansion 0.93 (hi) to 1.17 (fr), maximum 2.45 (a short French label). See `web/i18n/quality.json`.

## 7. Visual checks

Every language was rendered at desktop (1440×900), tablet (834×1112) and phone (390×844) widths in Chromium, and the
screenshots inspected (docs/screenshots/phase10/). See TEST_REPORT.md for what was looked at and what was found: Bangla conjuncts
and line breaking, Devanagari, German compounds, French and Spanish accents, scientific symbols, tables, charts, long navigation
labels, the settings dialog and exported reports.

## 8. Adding or changing a message

1. Write the English text in the code as before (or `_t("…")` on the server; `t("key")` with `en.json` for messages with
   parameters or plurals).
2. `python scripts/i18n_extract.py`, then `python scripts/i18n_merge.py --todo 100` lists untranslated messages.
3. Write a TSV batch (`key<TAB>bn<TAB>hi<TAB>es<TAB>fr<TAB>de`) and `python scripts/i18n_merge.py batch.tsv`. The merge refuses
   mismatched placeholders, empty text and replacement characters.
4. `python scripts/i18n_quality.py`, then `pytest tests/unit/test_phase10.py`.

## 9. Known limitations

- Translations are machine-made and unreviewed. Fluency and idiom have not been judged by native speakers; terminology has not
  been reviewed by astronomers working in those languages.
- Engine narrative text stays in English by design (see §2).
- Pattern matching translates rendered strings; a string assembled from several separately rendered pieces may stay partly in
  English if no catalogue message covers the whole. The observatory's runtime list shows such cases.
- Hindi uses Western digits by default (CLDR default for `hi`); Devanagari digits are not offered.
- Right-to-left scripts are not supported.
