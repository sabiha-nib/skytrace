# Epistemic methods (Phase 8)

Generated by `python scripts/gen_epistemic_methods.py` from the code and from the epistemic report the API serves for the two synthetic fixtures. Fixture results are known-answer checks of the software on generated data; they are not facts about the sky. No method here calls a model, uses a probability or produces a score.

## EPI-1 — scientific objects, epistemic statuses and the reasoning graph

Fifteen object kinds: source, observation, measurement, derived, transformation, method, model, assumption, uncertainty, inference, hypothesis, claim, limitation, contradiction, conclusion. Ten statuses: directly recorded, measured, derived, model-dependent, assumed, hypothesized, simulated, user-authored, unsupported, unknown. Each status comes from one rule that reads the object's origin and the method that produced it, never the wording of a sentence. Transformations and methods are procedures and carry no status. A trace is a breadth-first search over data edges, backward (what a result rests on) or forward (what depends on it).

| Rule | Statement |
|---|---|
| S1 | a file or observation from a synthetic bundle is 'simulated' (generated by code, not recorded by an instrument) |
| S2 | a file or observation from an archive bundle is 'directly recorded' |
| S3 | a quantity takes the producing method's output status (METHOD-DNA-1: measured / derived / model-dependent), or the least direct status among its inputs if that is further from the data (order: measured < derived < model-dependent) |
| S4 | analysis parameters, decision thresholds, models and method assumptions are 'assumed' (choices or premises, not results) |
| S5 | a competing explanation (HYPO-1) is 'hypothesized' |
| S6 | an inference (a stated rule applied to recorded values) is 'derived' |
| S7 | a claim takes the least direct status among the inferences that decide it; a claim with no supporting item is 'unsupported' |
| S8 | text written by the user in the session is 'user-authored' (applied in the browser) |
| S9 | a value the record does not determine is 'unknown' |
| S10 | uncertainty, limitation and contradiction records take the status of the rule that produced them ('derived') or are 'assumed' when they state a premise |

The wording check (used by compiler check C1, the claim-wording stress mode and firewall check I12) is negation-aware: an outcome word preceded within four words, in the same sentence, by one of cannot, never, no, nor, not, without is not an assertion. It can flag a sentence for review; it never sets a status.

## SCICOMP-1 — scientific compiler

Ten stages: Parse, Type checking, Dependency resolution, Assumption analysis, Method validation, Evidence validation, Uncertainty validation, Provenance validation, Conclusion review, Compilation report. Every check states its rule and returns pass, warning, fail or not applicable. Outcomes: valid under recorded rules, valid with warnings, incomplete, incompatible, unsupported claim, invalid provenance, requires scientific review.

Precedence: first match wins: a failed provenance check → invalid provenance; a failed type check → incompatible; a failed parse or dependency check → incomplete; a failed evidence or conclusion check → unsupported claim; a check that asks for review → requires scientific review; any warning → valid with warnings; otherwise valid under recorded rules

Every result carries the statement: *Passing means the investigation met these structural and methodological checks. It does not mean any conclusion is true.*

## SIMCHECK-1 — simulation audit

Generator identity, seeds, ground truth, noise and physical assumptions, simplifications and the validity domain, plus a repeated-seed test (up to 3 seeds). A synthetic benchmark tests the software against its own generator; it is not an observational validation dataset.

Noise assumptions: Gaussian pixel noise with variance noise² + 0.004 × (signal above sky); hot pixels flagged in FLAGS; noise is independent between pixels and exposures.

Simplifications: constant sky within a scenario; no zodiacal-light structure, cosmic rays or persistence; no aperture losses beyond the Gaussian PSF; a synthetic reference catalogue whose stars are exactly where the catalogue says (except the configured offset).

## Browser-side methods

* **VAULT-1** (`session.py`, `sessioncore.js`): each history entry's link is SHA-256(previous link + canonical entry). Edits break the chain and are refused on save; corrections are new entries. Tamper-evident, not a signature.
* **PROTOCOL-1** (`protocolui.js`): hypotheses, inputs, exclusions, parameters, expected outcomes and robustness tests; lock with content hash and time, labelled when results were visible; append-only amendments. Not preregistration.
* **BLINDLAB-1** (`protocolui.js`, `main.js`): hidden fields, a commitment hash, covered workspaces (renderers not called), copilot paused, ruler emphasis off; unblinding needs a locked protocol and typed confirmation; every step in the history.
* **ARG-1** (`argueui.js`): arguments from graph objects with a fixed list of inference rules; logical validity and empirical standing are reported separately.
